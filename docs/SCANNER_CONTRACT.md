# Scanner Contract

The backend treats SubMerge as a black-box reconnaissance engine and treats every later scanner as a modular enrichment stage. External tool output is normalized into the same internal model before writing to PostgreSQL.

## SubMerge

Input:

```bash
bash recon-engine/submerge.sh example.com
```

The backend does not parse banners, colors, or terminal formatting. It waits for the process to complete, then consumes files generated by SubMerge:

```text
output/example.com/
├── raw/
│   ├── amass.txt
│   ├── subfinder.txt
│   ├── assetfinder.txt
│   ├── findomain.txt
│   ├── all_initial.txt
│   └── all_final.txt
├── final/
│   ├── alive.txt
│   └── resolved.txt
└── run.log
```

`final/alive.txt` lines are parsed as live assets:

```text
https://api.example.com [200]
https://vpn.example.com [403]
```

`final/resolved.txt` lines are imported as DNS-resolved assets.

`run.log` is appended to the scan logs so analysts can view SubMerge execution history later.

## HTTPX

SubMerge already runs HTTPX for alive host detection. The platform does not run a second HTTPX stage by default. Later modules consume SubMerge's `alive.txt`.

## Modular Scanner Pipeline

Scanners implement:

```java
public interface ScannerModule {
    String name();
    void execute(ScannerContext context) throws Exception;
}
```

Registered modules are executed sequentially by `ScanOrchestrator`:

```text
SubMergeScanner
PortScanner
TechnologyScanner
HeaderScanner
ScreenshotScanner
WhoisScanner
SslScanner
DirectoryScanner
ApiDiscoveryScanner
NucleiScanner
RiskCalculatorModule
ReportGeneratorModule
```

Future scanners can be added by implementing `ScannerModule` and assigning an `@Order`.

## Nmap

Current command shape:

```bash
nmap -sV --open -oX <host>.xml <host>
```

Normalized fields:

- port
- protocol
- service
- version
- state

## WhatWeb

Current command shape:

```bash
whatweb --log-json whatweb.json https://host.example.com
```

Normalized fields:

- technologies
- headers
- framework fingerprints

## Nuclei

Current command shape:

```bash
nuclei -jsonl -l urls.txt
```

Normalized fields:

- finding name
- severity
- affected URL
- matched template
- CVE
- CVSS
- references
- recommendation

## Safe Default

`ASM_SCAN_MODE=mock` keeps demos safe and deterministic. `ASM_SCAN_MODE=tools` executes SubMerge and follow-on scanner modules. `demo` is not a real-tool mode.

## Current Real Mode Implementation

When `ASM_SCAN_MODE=tools`, the backend now executes and parses the real pipeline:

1. `bash recon-engine/submerge.sh <domain>`
2. Import `output/<domain>/final/alive.txt`
3. Import `output/<domain>/final/resolved.txt`
4. Append `output/<domain>/run.log` to scan logs
5. `nmap -sV --open -oX <host>.xml <host>`
6. `whatweb --log-json=<file> <url>`
7. Registered placeholder modules for headers, screenshots, WHOIS, SSL, directory enumeration, and API discovery
8. `nuclei -jsonl -l alive-urls.txt -o nuclei.jsonl`
9. Risk calculation and report stages

The normalized output is stored as:

- Assets from SubMerge and HTTPX
- Alive status, response code, title, IP, and HTTP technologies from HTTPX
- Open ports, protocol, service, version, and state from Nmap
- Additional technology fingerprints from WhatWeb
- Vulnerability findings, severity, CVE/CVSS, template, URL, and recommendation from Nuclei

## Local Real Mode Setup

Place your script here:

```text
recon-engine/submerge.sh
```

Create or edit `.env`:

```env
ASM_SCAN_MODE=tools
ASM_PROJECT_ROOT=..
SUBMERGE_PATH=recon-engine/submerge.sh
SUBMERGE_OUTPUT_ROOT=output
HTTPX_PATH=httpx
NMAP_PATH=nmap
WHATWEB_PATH=whatweb
NUCLEI_PATH=nuclei
SCAN_TIMEOUT_SECONDS=900
```

From the `backend` folder, start Spring Boot:

```powershell
mvn spring-boot:run
```

On Windows, the cleanest real-tool setup is usually WSL/Kali/Ubuntu with `bash`, `httpx`, `nmap`, `whatweb`, and `nuclei` installed and available in `PATH`. If you run the backend directly on Windows, make sure each configured executable can be launched from the same terminal that starts Spring Boot.
